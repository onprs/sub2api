# 订单、支付与兑换码

## 订单状态

| 状态 | 含义 | 用户操作 |
| --- | --- | --- |
| 待支付 | 已创建但尚未确认付款 | 在有效期内完成付款，或取消订单 |
| 已支付 / 处理中 | 支付已确认，正在发放余额或订阅 | 等待处理，不要重复支付 |
| 已完成 | 权益已成功发放 | 到余额、订阅和用量页面核对 |
| 已失败 | 权益发放遇到错误 | 保留订单号并联系支持处理重试 |
| 已取消 / 已过期 | 订单未在有效期完成 | 重新创建订单；不要继续支付旧码 |
| 退款处理中 / 已退款 | 正在等待支付渠道或已经完成退款 | 按订单状态等待，不要重复申请 |

支付回调可能延迟，付款页面关闭也不等于订单失败。先到[我的订单](https://cdn.api.onprs.top/orders)刷新状态。

## 避免重复支付

- 不要同时打开多个相同订单付款页面。
- 订单显示“已支付”或“处理中”时不要重新下单。
- 收到扣款通知但订单仍待支付时，记录支付时间和渠道交易号，等待短暂同步后联系支持。
- 不要把完整支付凭证公开；提交给支持前遮盖账号和无关交易。

## 余额冻结

普通套餐购买与余额充值按订单状态处理。批量图片任务会在提交时冻结预计费用：成功项按实际规则结算，未使用部分在完成或取消后释放。冻结金额不是重复扣款；若任务长期结束但冻结未释放，提交批次 ID 和请求时间。

## 退款

退款能力取决于订单类型、支付实例、权益是否已消耗和当前运营政策。控制台只会为符合条件的已完成余额订单显示用户退款入口；订阅、部分退款或异常订单可能需要支持人员处理。

退款可能经历“申请、处理中、渠道待确认、成功或失败”。权益扣减与支付渠道退款需要保持一致；不要在状态未决时重复申请。

## 兑换码类型

- 余额兑换码：增加或扣减余额。
- 并发兑换码：调整账号并发权益。
- 套餐兑换码：按分组和有效期发放订阅。
- 邀请码：用于注册流程，不能在普通兑换入口使用。

套餐型兑换码分为两类：

- 按套餐生成的新式兑换码：绑定套餐身份并保存三档额度快照；同套餐兑换会续期该套餐。
- 旧式按分组兑换码：没有套餐身份，续期分组级 legacy 权益，并保留已有滚动额度快照。

兑换码一次使用，可能有状态和到期时间限制。显示已使用、已过期或无效时，不要反复枚举；通过 [兑换码页面](https://cdn.api.onprs.top/redeem)核对后联系支持。
