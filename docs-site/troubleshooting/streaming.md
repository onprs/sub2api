# 超时、流与工具调用排查

## 首字超时

首字超时表示请求已经建立，但在客户端或网关等待期限内没有收到首个可输出事件。

1. 把请求改为非流式纯文本，判断模型是否能完成。
2. 缩短上下文，移除图片、工具和复杂 schema。
3. 检查客户端自己的 timeout，不只检查网络代理。
4. 换同分组另一个基础模型做对照。
5. 保留总耗时、首字时间和请求 ID。

设置合理的 timeout 上限，并继续检查模型容量、请求大小和重试策略。

## 流中断

记录最后一个完整 SSE 事件：

- Chat 正常应看到 `[DONE]`。
- Responses 应看到协议终止事件。
- Anthropic 应看到 `message_stop`。
- Google 流应正常结束数据事件。

若客户端报 JSON 解析失败，检查它是否把多行 SSE、keepalive 注释或另一协议终止符当成普通 JSON。

## 空响应

空响应的排查项包括文本字段读取、首个内容事件、模型拒绝和无文本的工具调用响应。

- 保存原始响应，不只看客户端 UI。
- 检查是否只有 `tool_calls`、reasoning 或图片内容。
- 用 curl 做非流式纯文本对照。
- 确认模型输出预算不为零或过小。

## 工具调用格式错误

1. 验证工具 schema 是有效 JSON Schema。
2. 参数使用合法的单层 JSON 编码。
3. 第二轮工具结果沿用原 `tool_call_id` / 调用 ID。
4. 两轮请求使用同一 Key、模型和 provider。
5. Google `functionResponse.response` 使用对象；Anthropic `tool_result.content` 应为文本或规范内容块。

## 客户端解析失败

curl 原始响应正常时，继续检查客户端：

- 升级到教程标明或更高的稳定版本。
- 确认 API mode 与实际端点一致。
- 关闭客户端“兼容修复”或第三方代理做对照。
- 先禁用流式，再逐项恢复工具、reasoning 和结构化输出。

提交支持时附上脱敏的最后一个原始事件、客户端报错和请求 ID。
